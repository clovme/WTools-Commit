# WTools-Commit

WTools 提交工具，用于批量管理 WTools 主仓库与其子模块的拉取、提交、推送、账号切换，以及大文件分卷打包/解包。

它的目标是：在多仓库/多子模块场景下，把“重复的 Git 操作”统一封装成一个可执行工具，减少手动步骤，并自动处理常见的账号、子模块、网络和大文件问题。

## 项目定位

这个工具本质上是一个面向 WTools 组织的 Git 协作辅助工具，适用于：

- 主仓库 + 子模块的批量同步
- 多账号 GitHub 场景下的凭据切换
- 大文件超过 GitHub 限制时的自动分卷处理
- 解决弱网环境下的 push/pull 失败重试
- 自动生成提交信息，减少手工填写

它不是一个通用 Git 客户端，而是“WTools 专用的仓库维护工具”。

## 主要功能

### 1. 批量 pull：拉取主仓库并同步全部子模块

命令：

```bash
commit pull
```

功能包括：

- 检查主仓库与子模块是否有未提交改动
- 若有未提交改动，则拒绝拉取，避免冲突
- 拉取主仓库远程更新
- 以 `merge --ff-only` 快进主仓库
- 初始化 / 更新所有子模块
- 让子模块跟随主仓库锁定的提交
- 在未登录的情况下，按“公开仓库拉取、私有仓库跳过”的方式降级处理

适用场景：

- 你想一次性同步整个 WTools 仓库树
- 你不想逐个手动 `git pull` 每个子模块

### 2. 批量 push：逐个提交并推送子模块，再提交主仓库

命令：

```bash
commit push
```

功能包括：

- 识别需要处理的子模块（工作区改动、已提交未推送、子模块指针变化等）
- 逐个子模块执行：
  - `git fetch`
  - 处理 detached HEAD
  - 切回跟踪分支
  - 自动提交本地改动
  - 安全快进到 `origin/<branch>`
  - push 到远端
- 主仓库随后再提交并推送：
  - 处理子模块指针更新
  - 处理主仓库本身的改动
- 如 push 失败，自动回滚本次提交，改动保留在工作区，避免丢失内容

优点：

- 一次性完成主仓库与各子模块的推送流程
- 减少“先改子模块再忘记更新主仓库指针”的问题

### 3. 账号自动识别与登录切换

命令：

```bash
commit login [用户]
commit logout [用户]
```

功能包括：

- 自动从 `origin` 和 `.gitmodules` 中解析远程 URL
- 提取主机和账号名，例如：
  - `https://github.com/win-tools/xxx.git` → `win-tools`
- 通过 Windows 凭据管理器（Git Credential Manager）统一管理 Git 登录状态
- 不依赖 `.gitconfig` 修改
- 如果多个仓库在同一主机上属于不同账号，会阻止“单凭据模式”继续，避免歧义
- 登录失败或取消时给出明确提示
- `logout` 可按指定用户注销，或全局清理当前主机凭据

适用场景：

- 多个 GitHub 账号在同一台机器上切换使用
- 需要在不同仓库之间切换权限，而不想手动改全局配置

### 4. 匿名模式拉取

当当前电脑未登录 GitHub 时，工具支持“匿名拉取”：

- 公共仓库可以正常拉取
- 私有仓库会跳过并汇总提示
- 不会因为未登录而直接中断整个流程

命令行为：

- `commit pull`：若未登录，则自动降级匿名模式
- `commit push`：未登录则直接中止，避免错误推送

### 5. 自动识别分支、处理 detached HEAD

工具设计了分支解析逻辑：

- 优先使用当前分支
- 若当前处于 detached HEAD，则优先尝试 `origin/HEAD`
- 若没有 `origin/HEAD`，则尝试 `main` / `master` 中存在的那个
- 若仍无法确定，则给出明确错误提示

好处：

- 不依赖手工猜测分支
- 在不稳定的仓库状态下也能尽量保持正确行为

### 6. 自动生成提交信息

在 push 流程中，工具会：

- 先执行 `git add -A`
- 读取 `git diff --cached --name-status`
- 把变更摘要整理成提交信息
- 如果没有取到有效摘要，则回退为固定信息：

```text
^Q^
```

这样就不需要每次手动填写提交信息。

### 7. 自动处理子模块同步和分叉问题

工具在处理子模块时会：

- 初始化子模块
- 让子模块跟着远程分支
- 若远程领先，执行安全快进
- 若本地和远程已分叉，拒绝误操作并给出明确提示
- 若本地在 push 过程中失败，自动回滚本次提交，不丢本地改动

这是 WTools 这类“子模块较多”的仓库最关键的能力之一。

### 8. 处理 GitHub 超大文件

GitHub 对单个文件有严格限制：

- 100MB 以上会被直接拒绝
- 50MB 以上会抛出建议警告

工具做了大量兼容处理：

- 在 push 前检查未推送历史中是否包含大文件
- 若遇到超大文件：
  - 自动回退未推送提交
  - 使用 7z 分卷压缩
  - 重新 commit
  - 再次 push
- 对未推送提交中的超大文件，提前本地发现并规避，避免传输大半天才被拒绝

### 9. 7z 分卷打包 / 解包

命令：

```bash
commit pack <路径>
commit unpack
```

功能包括：

- 把大文件或目录压缩成多卷 7z 分卷
- 默认使用 50MB/卷，确保每卷低于 GitHub 建议容量
- 输出格式类似：

```text
源文件名[pack].7z.001
源文件名[pack].7z.002
...
```

- 自动把源文件加入 `.gitignore`
- 对已跟踪文件执行 `git rm --cached`，保留本地文件
- 支持解压已存在的 `[pack]` 分卷，恢复原始目录结构

适用场景：

- 需要把超大资源文件托管到 GitHub
- 希望保留本地文件，但不把原始大文件直接提交进 Git

### 10. 网络异常重试与稳健推送

工具不仅处理逻辑错误，也处理网络异常：

- 在 push 时检测 `RPC failed`、HTTP 408/5xx、连接中断、`early EOF` 等错误
- 自动重试，并逐步增加缓冲参数：
  - `http.postBuffer`
  - `http.lowSpeedTime`
- 在遇到真正的鉴权、冲突、非快进等错误时，不继续无意义重试

这样能明显提高弱网环境下的成功率。

## 使用方式

### 1. 拉取

```bash
commit pull
```

用于：

- 拉取主仓库更新
- 初始化/同步子模块
- 处理未登录时的匿名拉取退化

### 2. 推送

```bash
commit push
```

用于：

- 提交子模块改动
- 提交主仓库修改
- 自动处理大文件
- 自动生成提交信息

### 3. 登录

```bash
commit login
commit login <用户名>
```

用于：

- 切换 GitHub 账号
- 自动识别仓库对应账号
- 通过浏览器登录 Git Credential Manager

### 4. 注销

```bash
commit logout
commit logout <用户名>
```

用于：

- 清除对应 Git 凭据
- 解除当前账号的 GitHub 登录状态

### 5. 大文件打包

```bash
commit pack <路径>
commit pack <路径> best
```

说明：

- 支持文件或目录
- 7z 自动多分卷压缩
- 归档会生成在源文件同目录
- 源文件会被忽略并保留本地文件

### 6. 解包

```bash
commit unpack
```

用于：

- 扫描仓库内所有 `[pack]` 分卷
- 还原大文件/目录
- 适合新克隆后恢复资源

## 目录与运行要求

### 运行要求

- Windows 环境（项目中大量调用 Windows 凭据管理器和 Git Credential Manager）
- Git 已安装并可访问
- 7-Zip（`7z.exe`）放在项目根目录、PATH 中，或常见安装目录中
- 将 `commit.exe` 放在 WTools 根目录中运行，确保它能识别整个仓库结构

### 项目结构

```text
WTools-Commit/
├─ src/
│  └─ main.rs             # 主程序逻辑
├─ Cargo.toml             # Rust 项目配置
├─ Cargo.lock
├─ .gitignore
├─ README.md
└─ ...
```

## 设计亮点

这个程序的价值，不单是“封装了 git pull / git push”，而在于它把以下一系列难点统一处理掉：

- 子模块批量操作
- GitHub 账号切换
- 凭据管理
- 匿名拉取
- 大文件限制
- 网络重试
- detached HEAD
- 提交信息自动生成
- 自动回滚与恢复

也就是说，它更像一个“WTools 仓库维护脚本 + 自动化 Git 助手”。
